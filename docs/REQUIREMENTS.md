# Requirements and Acceptance Criteria

Source: the existing mini task manager requirements in _docs/REQUIREMENT.MD and the user's requested changes in this conversation. Existing workflow and audit invariants remain in force unless an approved decision supersedes them.

| ID      | Requirement                                                                                | Acceptance criteria                                                                                                                                                                                                                                                                                                                                                                                                                 | Edge cases                                                                                                                                     | Planned implementation                                                                                                                                                                   | Planned tests                                                                                                                           | Status                    |
| ------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| REQ-001 | Persist application data in MongoDB instead of hard-coded/file JSON data.                  | AC-001.1 Given a configured MongoDB URI, the API stores and reloads boards, tasks, and audit events across restarts. AC-001.2 Missing/invalid database configuration produces a clear startup failure. AC-001.3 All user-facing data is read from the repository, never fixture constants.                                                                                                                                          | EC-001: unavailable database, malformed URI, reconnect, empty collections.                                                                     | Add Mongo repository and validated environment configuration; remove JSON repository from production wiring.                                                                             | Repository integration tests against a dedicated, non-production MongoDB Atlas test database; restart/persistence check; config tests.  | Planned                   |
| REQ-002 | Replace click-to-advance controls with a Kanban board.                                     | AC-002.1 Tasks render in status columns with their current status visible. AC-002.2 A deliberate drag/drop moves a task and persists the new status. AC-002.3 Invalid/skipped transitions are rejected and the card remains in its original column. AC-002.4 Status changes still obey the approved transition order and append audit history.                                                                                      | EC-002: drop outside a lane, same-lane drop, skipped/backward transition, concurrent move, failed request.                                     | Build accessible board/column/card components and a drag-and-drop interaction; keep transition validation authoritative on the backend.                                                  | Playwright: create and move a card; invalid drop; failed API move; keyboard/accessibility path if supported by selected DnD library.    | Planned                   |
| REQ-003 | Allow users to customize board and/or task configuration.                                  | AC-003.1 User can persist and reload the approved board configuration. AC-003.2 User can customize the approved column/status and task-field scope. AC-003.3 Existing tasks and audit history remain coherent after configuration edits.                                                                                                                                                                                            | EC-003: duplicate/blank column names, removing/reordering a column with tasks, incompatible custom-field values, historic labels after rename. | Add board configuration APIs and persisted board/task-field schema. Exact configuration scope and lifecycle are pending user clarification.                                              | API tests for valid/invalid configuration; Playwright configuration and reload flow; migration/history cases.                           | Blocked on scope decision |
| REQ-004 | Improve the Acting as selector UX while retaining clear attribution.                       | AC-004.1 The selected actor is clearly visible and understandable before a move. AC-004.2 Every successful status change records that actor. AC-004.3 The selector supports the approved actor list and accessible keyboard interaction.                                                                                                                                                                                            | EC-004: no actor selected, removed/unknown actor, rapid actor change during a pending move.                                                    | Replace the basic native select with a focused, accessible actor picker and clear selected-state presentation. Keep identity self-selected unless authentication is separately approved. | Component and Playwright tests for selection, keyboard use, and attribution on move.                                                    | Planned                   |
| REQ-005 | Show who last updated each task.                                                           | AC-005.1 After a status move, the card shows the Updated by label and actor handle alongside last-update time. AC-005.2 The same actor and timestamp are returned by the API after reload. AC-005.3 Initial tasks show an honest created-by/initial-state presentation rather than a fabricated updater.                                                                                                                            | EC-005: task has no prior status move, actor display name changes, deleted actor identity.                                                     | Persist updatedBy (or actor ID) with task status and return it in task views.                                                                                                            | Service/API tests plus Playwright verification before/after a move and reload.                                                          | Planned                   |
| REQ-006 | Preserve immutable, chronological audit history and state consistency.                     | AC-006.1 Every real status transition appends exactly one audit event containing task identity/title snapshot, actor, from/to status, and timestamp. AC-006.2 A no-op creates no audit event. AC-006.3 An invalid move creates neither a task change nor an event. AC-006.4 Audit events cannot be edited/deleted through any API. AC-006.5 Deleting a task preserves historical events. AC-006.6 Events are returned oldest-first. | EC-006: transaction failure, duplicate request, simultaneous transitions, deleted task, equal timestamps, renamed/removed status labels.       | Keep audit events in a separate append-only collection; update task plus insert event in one Mongo transaction; snapshot labels/title in the event.                                      | Service and API tests for no-op, invalid move, atomic rollback, retention after delete, ordering, and absence of mutating audit routes. | Planned                   |
| REQ-007 | Split backend routes by endpoint/domain for maintainability.                               | AC-007.1 Task, board/configuration, and audit route modules are separate files. AC-007.2 Route handlers delegate validation/business rules to services. AC-007.3 Existing public behavior is covered by API tests.                                                                                                                                                                                                                  | EC-007: malformed request, unknown route, not found, storage failure, invalid identifier.                                                      | Organize route modules, controllers/services, validation, Mongo models/repositories, and shared error handling into clear folders.                                                       | Route-level integration tests for success and error responses; import/build check.                                                      | Planned                   |
| REQ-008 | Split frontend into maintainable file-based components.                                    | AC-008.1 Board, column, task card, actor picker, task form/configuration, and audit detail are focused components. AC-008.2 Shared API/types/hooks are not duplicated across components. AC-008.3 Current loading, empty, error, and success states remain clear.                                                                                                                                                                   | EC-008: empty board, loading, API rejection, narrow viewport, long task title, no logs.                                                        | Create small React components and typed API/state modules while preserving simple product flows.                                                                                         | Component tests where useful and Playwright coverage of primary flows and failure states.                                               | Planned                   |
| REQ-009 | Publish API documentation with Scalar.                                                     | AC-009.1 OpenAPI describes every implemented public endpoint, request/response, status/error shape, and authentication assumption. AC-009.2 Scalar UI is reachable at the documented API docs URL. AC-009.3 Spec and implementation agree.                                                                                                                                                                                          | EC-009: stale/malformed schema, validation error examples, docs endpoint unavailable.                                                          | Maintain an OpenAPI document and mount Scalar in Express (proposed /api/docs with a JSON spec endpoint).                                                                                 | Schema validation and smoke check for docs page/spec; compare route contracts in API tests.                                             | Planned                   |
| REQ-010 | Test inputs and behavior across frontend and backend; use Playwright for frontend testing. | AC-010.1 Backend validates required/trimmed input, identifiers, actor, workflow, and board/task configuration. AC-010.2 Automated tests cover valid, invalid, missing, duplicate/no-op, persistence, and failure cases. AC-010.3 Playwright covers create, board move, actor attribution, update display, customization, audit history, and visible errors.                                                                         | EC-010: whitespace/oversize input, wrong JSON types, network/database failure, browser reload.                                                 | Define validation at API boundaries and add layered unit, Mongo/API integration, component, and browser E2E suites.                                                                      | Node test runner or Vitest + Supertest for backend; Playwright for browser. Exact tools/CI setup confirmed in task breakdown.           | Planned                   |
| REQ-011 | Preserve original task-manager behaviors and guardrails.                                   | AC-011.1 Create/list/delete tasks remain available. AC-011.2 Default ordered workflow remains to_do -> pending -> in_progress -> done unless the approved custom-board decision defines a compatible extension. AC-011.3 Task deletion does not delete audit events. AC-011.4 No auth/roles or unrelated product scope is introduced without approval.                                                                              | EC-011: empty list, missing task, invalid state transition, deleted-task history access.                                                       | Extend the existing React/Express TypeScript application rather than replace the stack.                                                                                                  | Regression coverage in service/API/Playwright suites.                                                                                   | Planned                   |
